# 概念旁路查询

一个本地静态网页原型，用来把大模型的线性回答变成可回溯的概念旁路阅读界面。

当你询问一个概念时，回答里常常会引出新的术语。继续追问新术语会打断原来的主线。本项目把每次回答显示为横向卡片：主卡片保留在原位，正文中被标注的术语和底部推荐关键词都可以继续展开成下一张卡片。

![preview](src/image-1.png)

## 当前状态

- 本地静态网页，直接打开 `index.html` 使用。
- 默认使用 DeepSeek Chat Completions API。
- 无后端、无本地知识库、无缓存。
- 每次查询都实时请求模型。
- UI 采用先锋主义/构成主义风格：红黑米白、高对比、硬边框、斜切构图。
- 模型自由生成正文，不强制固定段落结构。
- 正文术语由模型二次标注，避免浏览器分词把完整概念切碎。

## 核心流程

每生成一张卡片，会进行两次模型调用：

1. **生成解释**
   - 输入：当前概念、父概念上下文、理解路径。
   - 输出：标题、标签、自由正文、推荐关键词。

2. **术语标注**
   - 输入：第一步生成的正文。
   - 输出：正文中原样出现的完整术语短语。
   - 目的：把“进程间通信 (IPC)”这类完整概念作为整体标注，而不是拆成碎片。

如果第二次术语标注失败，页面会退回到底部推荐关键词。

## 使用方式

1. 打开 `index.html`。
2. 填写 DeepSeek API Key。
3. 输入主概念，例如 `进程`、`线程`、`mmap`、`页表`。
4. 点击“生成”。
5. 点击正文中带下划线的术语，或点击底部推荐关键词，继续展开下一张卡片。

默认配置：

```txt
API: https://api.deepseek.com/chat/completions
Model: deepseek-v4-flash
```

## 模型协议

第一次调用要求模型返回：

```json
{
  "title": "概念名",
  "type": "标签",
  "answer": "自由格式正文，可以包含简单 Markdown",
  "keywords": [
    {
      "text": "关键词",
      "query": "带上下文的后续查询意图",
      "reason": "为什么值得继续展开"
    }
  ]
}
```

第二次调用要求模型返回：

```json
{
  "terms": [
    {
      "text": "正文中原样出现的完整术语短语",
      "query": "带上下文的后续查询意图",
      "reason": "为什么值得展开"
    }
  ]
}
```

## 设计取舍

- **不使用本地知识库**：知识完全来自模型实时生成。
- **不缓存**：同一个词再次展开会重新请求模型。
- **不做浏览器分词**：由模型抽取完整术语，质量更高，但会增加一次请求。
- **不做后端代理**：部署最轻，但可能受浏览器 CORS 限制。

## 已知限制

- 每张卡片两次模型调用，速度和 API 消耗高于单次生成。
- 浏览器直连 DeepSeek API 时，如果网络环境或接口策略限制 CORS，请求可能失败。
- API Key 只存在当前页面内存中，刷新页面后需要重新填写。
- 模型返回 JSON 不稳定时，页面可能显示请求失败。

## 后续方向

- 增加本地代理，解决 CORS 和 Key 暴露问题。
- 增加可选缓存，减少重复请求。
- 支持导出理解路径。
- 支持固定某张卡片或为卡片添加笔记。
- 支持选择术语标注强度：少而准 / 平衡 / 尽可能多。
